## Overview

`turbomcp-macros` provides the procedural macros for TurboMCP development. The macros
discover handler methods inside an `impl` block, parse their signatures, and generate a
full `McpHandler` implementation plus JSON schemas for the tool inputs.

Schema generation uses `schemars` and is always enabled — it is not an optional feature.

Use the macros through the `turbomcp` crate (`use turbomcp::prelude::*;`): the
generated code refers to `turbomcp`'s re-exports.

## Exported Macros

| Macro | Role |
|---|---|
| `#[server]` | Transforms an `impl` block into a full `McpHandler` implementation |
| `#[tool]` | Marks a method as a tool handler |
| `#[resource]` | Marks a method as a resource handler |
| `#[prompt]` | Marks a method as a prompt handler |
| `#[completion]` | Marks the `completion/complete` handler |
| `#[subscribe]` / `#[unsubscribe]` | Mark the `resources/subscribe` and `resources/unsubscribe` handlers |
| `#[set_level]` | Marks the `logging/setLevel` observer |
| `#[roots_changed]` | Marks the `notifications/roots/list_changed` handler |
| `#[description]` | Attaches a description to a tool or prompt parameter |

Every marker except `#[description]` must be inside a `#[server]` block; used
outside one, it emits a compile error with a usage example. `#[title]` on a
prompt parameter is read by `#[server]` and is not a separate macro.

## `#[server]`

Applies to an inherent (non-trait) `impl` block. Generates an `impl McpHandler` for
the struct that dispatches tool / resource / prompt calls to the annotated methods.

**Supported arguments** (each value is an expression, so it can come from
`env!` or a `const`):

- `name = "..."` — Server name. Defaults to the struct identifier.
- `version = "..."` — Server version. Defaults to `"1.0.0"`.
- `description = "..."` — What this implementation is.
- `title = "..."` — Human-readable display name.
- `instructions = "..."` — How to use the server; returned in the `initialize` result.
- `website_url = "..."` — Homepage for this implementation.
- `icons = ["https://…/icon.png"]` — Icon sources.
- `page_size = N` — Paginate `tools/list`, `resources/list`, `resources/templates/list`,
  and `prompts/list` at `N` entries.
- `logging` — Accepted for compatibility; has no effect.

An unknown key is a compile error that lists the accepted ones. The removed
`transports = [...]` argument is rejected with a diagnostic directing you to Cargo
feature flags instead.

The generated `McpHandler` advertises exactly the capabilities the block serves:
`tools`, `resources`, and `prompts` for the handlers present, `completions` for a
`#[completion]` handler, `resources.subscribe` for `#[subscribe]`, and `logging`
always, since every server can send log messages and accepts `logging/setLevel`.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Calculator;

#[server(
    name = "calculator",
    version = env!("CARGO_PKG_VERSION"),
    instructions = "Call `add` for arithmetic."
)]
impl Calculator {
    /// Add two numbers
    #[tool]
    async fn add(&self, a: f64, b: f64) -> f64 {
        a + b
    }
}
```

The runner methods (`run_stdio`, `run_http`, `run_tcp`, `run_unix`, `run_websocket`)
are defined on the `McpHandlerExt` trait in `turbomcp-server`, which is
blanket-implemented for every `McpHandler`. They are *not* generated by this macro;
the macro's job is only to produce the `McpHandler` impl.

## `#[tool]`

Marks a method as a tool handler. The tool name is the method identifier, and the
tool description is taken from doc comments unless overridden via the attribute.

**Supported argument forms:**

- `#[tool]` — no arguments; description comes from the `///` doc comment.
- `#[tool("description")]` — shorthand for the description.
- `#[tool(description = "...", tags = ["a", "b"], version = "1.0")]` — named arguments.

`#[tool]`, `#[resource]`, and `#[prompt]` share one attribute grammar. All three accept
`description`, `title`, `tags`, `version`, and `icons`; an explicit `description` takes
precedence over the doc comment. `#[tool]` adds `read_only`, `destructive`,
`idempotent`, `open_world` (the `ToolAnnotations` hints), `output_schema = Type`, and
`task_support = "forbidden" | "optional" | "required"` (advertised as
`execution.taskSupport`). An unknown key is a compile error that lists the accepted
ones.

A raw identifier is advertised without its prefix: `async fn r#type` is the tool `type`,
and a parameter `r#match` is the argument `match`.

A tool returns anything that implements `IntoToolResult`: `String`, numbers, `bool`,
`()`, `serde_json::Value`, `Vec<T: Serialize>`, `Json<T>` (sent as
`structuredContent`, with `T`'s schema advertised as `outputSchema`), `ToolResult`,
or a `Result`/`McpResult` of those. An `McpError` is reported as a tool execution
error (`isError: true`) with its kind in `_meta`.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Greeter;

#[server]
impl Greeter {
    /// Greet someone by name
    #[tool(read_only = true, idempotent = true)]
    async fn greet(
        &self,
        #[description("Name of the person to greet")] name: String,
        #[description("Optional greeting prefix")] prefix: Option<String>,
    ) -> String {
        let prefix = prefix.unwrap_or_else(|| "Hello".into());
        format!("{prefix}, {name}!")
    }
}
```

**Input schema rules:**

- `&self` is skipped.
- Parameters whose type is `Context`, `RequestContext`, `&Context`, or `&RequestContext`
  are recognized as context and excluded from the schema.
- Remaining parameters become schema properties; `Option<T>` parameters are optional,
  everything else is required.
- Parameter types are passed through `schemars::schema_for!` at compile time.

## `#[resource]`

Marks a method as a resource handler. The first argument is the resource URI, or an
RFC 6570 URI template.

**Supported argument forms:**

- `#[resource("uri://template")]`
- `#[resource("uri://template", mime_type = "application/json")]`
- `#[resource("uri://template", description = "...", tags = ["..."], version = "1.0")]`
- `#[resource("uri://x", audience = ["user", "assistant"], priority = 0.8,
  last_modified = "2025-01-12T15:00:58Z", size = 1024)]` — the `ResourceAnnotations`
  and the size in bytes (`size` on concrete URIs only)

The shared keys (`description`, `title`, `tags`, `version`, `icons`) work as on
`#[tool]`.

The handler takes `(uri: String, ctx: &RequestContext)` and returns `McpResult<T>`
for any `T: IntoResourceResult` (`String`, `&str`, `ResourceResult`). A template's
variables are not bound to parameters: the handler receives the full URI and parses
what it needs. Concrete URIs are matched before templates, whatever the declaration
order.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Files;

#[server]
impl Files {
    /// Application configuration
    #[resource("config://app", mime_type = "application/json")]
    async fn config(&self, uri: String, ctx: &RequestContext) -> McpResult<String> {
        Ok(r#"{"debug": false}"#.to_string())
    }

    /// Read a file by path
    #[resource("file://{path}")]
    async fn file(&self, uri: String, ctx: &RequestContext) -> McpResult<String> {
        let path = uri.trim_start_matches("file://");
        Ok(format!("Content of {path}"))
    }
}
```

## `#[prompt]`

Marks a method as a prompt handler. Arguments are optional; a bare `#[prompt]` uses
the method's doc comment as the prompt description, and `#[prompt("...")]` sets it
directly. The prompt's name is the method name.

Parameters other than `&self` and the context are the prompt's arguments. Each is a
`String` (required) or an `Option<String>` (optional), and the handler takes
`ctx: &RequestContext` last. It returns anything that implements `IntoPromptResult`
(`String`, `PromptResult`, `Vec<Message>`), or a `Result` of one; an error is a
JSON-RPC error rather than a message.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Prompts;

#[server]
impl Prompts {
    /// Generate a greeting prompt
    #[prompt]
    async fn greeting(&self, name: String, ctx: &RequestContext) -> String {
        format!("Hello {}! How can I help you today?", name)
    }

    /// Generate a code review prompt
    #[prompt]
    async fn code_review(
        &self,
        #[title("Language")]
        #[description("Language the code is written in")]
        language: String,
        #[title("Review style")] style: Option<String>,
        ctx: &RequestContext,
    ) -> McpResult<PromptResult> {
        let style = style.unwrap_or_else(|| "concise".to_string());
        Ok(PromptResult::user(format!("Review this {language} code in a {style} style")))
    }
}
```

## Optional handlers

Five markers opt into the MCP methods a server may leave out. Each may appear at
most once, takes an optional trailing `ctx: &RequestContext`, and returns
`McpResult<_>`. Without one, the method answers `capability_not_supported` and the
capability stays unadvertised.

| Marker | Signature | Serves | Advertises |
|---|---|---|---|
| `#[completion]` | `(&self, params: serde_json::Value) -> McpResult<serde_json::Value>` | `completion/complete` | `completions` |
| `#[subscribe]` | `(&self, uri: String) -> McpResult<()>` | `resources/subscribe` | `resources.subscribe` |
| `#[unsubscribe]` | `(&self, uri: String) -> McpResult<()>` | `resources/unsubscribe` | — |
| `#[set_level]` | `(&self, level: String) -> McpResult<()>` | `logging/setLevel` | — (`logging` is always advertised) |
| `#[roots_changed]` | `(&self) -> McpResult<()>` | `notifications/roots/list_changed` | — |

`#[subscribe]` without `#[unsubscribe]` is a compile error: a client must be able to
cancel a subscription the server accepted. `logging/setLevel` works without
`#[set_level]` (the level is recorded per session and filters log notifications);
declare it only to observe the change. Returning an error from it rejects the
request and keeps the previous level.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Docs;

#[server(name = "docs", version = "1.0.0")]
impl Docs {
    /// A documentation page
    #[resource("docs://{page}")]
    async fn page(&self, uri: String, ctx: &RequestContext) -> McpResult<String> {
        Ok(format!("contents of {uri}"))
    }

    /// `params` is the raw `completion/complete` params: `{ ref, argument, context? }`
    #[completion]
    async fn complete(&self, params: serde_json::Value) -> McpResult<serde_json::Value> {
        let prefix = params["argument"]["value"].as_str().unwrap_or("");
        let values: Vec<&str> = ["intro", "install", "api"]
            .into_iter()
            .filter(|page| page.starts_with(prefix))
            .collect();
        Ok(serde_json::json!({ "completion": { "values": values } }))
    }

    /// Send `notifications/resources/updated` with `ctx.notify_resource_updated(uri)`
    #[subscribe]
    async fn watch(&self, uri: String, ctx: &RequestContext) -> McpResult<()> {
        Ok(())
    }

    #[unsubscribe]
    async fn unwatch(&self, uri: String, ctx: &RequestContext) -> McpResult<()> {
        Ok(())
    }

    /// `level` is the validated spec string: "debug", "info", … "emergency"
    #[set_level]
    async fn level_changed(&self, level: String) -> McpResult<()> {
        Ok(())
    }

    /// Re-query `ctx.list_roots()` and drop any cached roots
    #[roots_changed]
    async fn roots_changed(&self, ctx: &RequestContext) -> McpResult<()> {
        Ok(())
    }
}
```

## `#[description]` and `#[title]`

`#[description]` attaches a description to a parameter; it becomes the JSON Schema
`description` of a tool property, or the `description` of a prompt argument. On a tool
parameter both forms are accepted:

- `#[description("text")]`
- `#[description = "text"]`

A prompt parameter takes the `#[description("text")]` form, and may also carry
`#[title("...")]`: a display label for clients that render a prompt-argument form.

```rust
use turbomcp::prelude::*;

#[derive(Clone)]
struct Search;

#[server]
impl Search {
    /// Search the index
    #[tool]
    async fn search(
        &self,
        #[description("The search query string")] query: String,
        #[description = "Maximum number of results"] limit: Option<u32>,
    ) -> Vec<String> {
        vec![format!("{query} (up to {})", limit.unwrap_or(10))]
    }
}
```

## How schemas are generated

Each non-context parameter is run through `schemars::schema_for!(T)` at macro
expansion time. The resulting schema is merged into an object schema with:

- `type: "object"`
- `properties`: one entry per parameter, with any `#[description(...)]` string
  merged in
- `required`: names of non-`Option` parameters
- `additionalProperties: false`, which the dispatcher enforces: an argument the tool
  does not take is reported as a tool execution error

Complex user-defined types work automatically as long as they implement
`schemars::JsonSchema` (usually via `#[derive(JsonSchema)]`).

## Context injection

Any parameter whose type resolves to `Context` or `RequestContext` (owned or `&`)
is recognized as the request context. It is excluded from the generated schema and
wired from the dispatcher at call time. On a tool it may appear in any position in
the signature; resource and prompt handlers take it last.

## Feature flags

The macro crate itself has a small set of features that gate optional dependencies
needed by generated code that uses certain transports:

| Feature | Enables |
|---|---|
| `http` | pulls in `axum` for HTTP-related code paths |
| `tcp` | pulls in `tokio` and `turbomcp-transport` |
| `unix` | pulls in `tokio` and `turbomcp-transport` |
| `experimental-tasks` | pass-through to `turbomcp-protocol/experimental-tasks` |

In practice you enable the matching features on the umbrella `turbomcp` crate and
the dependency graph resolves these transitively. `schemars` is always required.
